## 1. The mission, in one paragraph

`evryn-team-runtime` is the autonomous harness for Evryn's 8 founding-team agents (ADR-050), **dormant by construction** until the Meta-Meeting. When the runtime composes an agent's wake it fetches that agent's rooms with a PostgREST `.in('thread_id', [...])` filter — **and that id list goes into the URL.** Past roughly **370 ids** the request exceeds the server's URL length limit and returns **HTTP 414**. **The throw escapes `composeWake`, which sits OUTSIDE `runWake`'s try/catch — so it is not a degraded wake, it is NO wake at all, for that agent, every time, until someone notices.** Your job: make a large room-count survivable, and make sure that if it ever *does* fail, it fails loudly instead of silently deleting an agent from the team.

**Why this matters now rather than later:** eight agents, each in many rooms, is exactly the shape the Meta-Meeting creates. **This is pre-existing on `main` — it was surfaced by the ACfr pagination lane and deliberately NOT folded into it** (route-don't-fold: a rider arrives with none of the review attention aimed at it).

### 2b. ⚠️ TWO FINDINGS THAT CHANGE THE SHAPE OF THE TRIP — added 2026-08-10, after the brief was first written

**(i) 🔴 THE EXISTING PAGINATION DOES NOT HELP HERE, AND §3 BELOW WILL POINT YOU AT IT ANYWAY.** `readThreadDigestRows` is **already** wrapped in `paginateAll` — and the `.in('thread_id', threadIds)` sits **INSIDE the `page` callback** (`digest/index.ts:126-136`), so **every page request re-sends the entire id list in the URL.** Paging bounds how many *rows* come back; the 414 is about how long the *request* is. **They are orthogonal axes, and the request fails on page one.** ⚠️ **So the instinct §3 encourages — "we have `paginate.ts`, extend it" — is a trap in its simplest form.** A correct fix almost certainly chunks the **id list** *and* paginates **rows within each chunk**; that is two dimensions, not one, and `paginateAll`'s ascending-cursor contract has to survive inside each chunk. **Establish this yourself before you design — it is the single highest-leverage thing to get right on day one.**

**(ii) The surface grows monotonically and never shrinks — so this is not "an agent in 370 live rooms."** `readEverMemberThreadIds` (`digest/index.ts:89-106`) reads `thread_subscriptions` with **no `dismissed_at` filter** (deliberate — ever-member visibility is by design) and **no state filter**; nothing in `src/` ever `DELETE`s a subscription row, and dormancy never reverses (Step 7 / `L12`). The `.neq('state','dormant')` at `:133` is applied **server-side, after** the ids are already in the URL, and the scratchpad read at `composer/index.ts:210` has no state filter at all. **⇒ The list includes every room the agent has EVER been in — left rooms and dormant rooms alike, forever.** For a long-lived Lucas the wall arrives materially sooner than "370 concurrent rooms" implies. **A cheap partial mitigation worth weighing — pre-filtering the id list by state BEFORE it reaches the URL — is both semantically right and shrinks the surface, but it does NOT close the class, so treat it as an addition to chunking and never a substitute.**

**Bounded, and deliberately NOT in scope** (confirm rather than assume, then leave them alone): `safety/kill.ts:74` and `wakes/capabilities.ts:99` take a fixed 2-element array; `scheduler/index.ts:364` takes `ACTIVE_AGENTS`; `scheduler/index.ts:410/422` take ids from queries already bounded by `.limit()`.

**The blast radius, traced rather than assumed:** `runWake` calls `composeWake` at `src/wakes/index.ts:229`; its first `try {` is at line **312**. So a throw inside composition propagates out of `runWake` entirely, reaches the scheduler's dispatch catch, and the trigger is never marked processed. **⚠ Establish for yourself what happens next** — whether that retries forever (a ping storm, the L9 wedge shape) or drops — because *which* it is changes how loud the fix has to be. **Do not take that from this brief; go read the dispatch path and prove it.**

## 3. ACf's design position — you may overrule it

**Two things need to be true, and they are separable:**

1. **A large room count must WORK.** The natural fix is to chunk the id list into batches comfortably under the URL limit and merge the results. **Read `src/db/paginate.ts` first** — but read it against **§2b(i) above**, which corrects this bullet's original steer: that module solves the **row-ceiling** axis and the `.in()` list is already *inside* its page callback, so "just extend it" is not the win it sounds like. **You are adding a second dimension (chunk the ids) around an existing one (paginate the rows), not extending one.** Whether that lands as an extension or a wrapper is yours to decide *after* you have read it.
   - ⚠️ **On result assembly — one of the two worries this bullet used to raise is already handled, so don't spend time on it.** **De-duplication** is safe by construction if your chunks partition the id set, since `thread_id` is the primary key of `thread_digests`. **Ordering is also already safe:** the composer **re-sorts in JS after the read** (`composer/index.ts:193-198`, newest-activity-first with NULLs first to reproduce Postgres `DESC NULLS FIRST`), so it does **not** depend on read order. **The real constraint is narrower: `paginateAll`'s ascending-cursor contract must still hold WITHIN each chunk.** *(Spot-verified by ACf; re-derive it.)*
2. **A composition failure must never silently delete an agent from the team.** Even fixed, this is a *class*: composition can throw for reasons nobody has thought of yet, and today any such throw yields no wake and no alert. ⚠️ **And per §2b, this half now has a second, concrete target: the `try/catch` at `digest/index.ts:473-509` that logs a 414 as `"non-fatal."`** That catch is *correct in intent* — a digest freshen genuinely must never fail a wake — but it currently cannot distinguish "one blurb didn't refresh" from "this agent's entire room list is un-fetchable." **A failure that is genuinely non-fatal to the wake can still be fatal to the system, and saying "non-fatal" about it is how it stays invisible for a month.** Whatever loudness you build must reach *that* path too, not only the propagating one. **⇒ ACf's lean, which is the more valuable half of this trip: give the composition path the same treatment the boot path got — a loud, uniform failure.** The runtime already has the pattern (`src/safety/emergency.ts`, and `runWake`'s own park-and-ping).
