## 1. The mission, in one paragraph

`evryn-team-runtime` is the autonomous harness for Evryn's 8 founding-team agents (ADR-050), **dormant by construction** until the Meta-Meeting. When the runtime composes an agent's wake it fetches that agent's rooms with a PostgREST `.in('thread_id', [...])` filter — **and that id list goes into the URL.** Past roughly **370 ids** the request exceeds the server's URL length limit and returns **HTTP 414**. **The throw escapes `composeWake`, which sits OUTSIDE `runWake`'s try/catch — so it is not a degraded wake, it is NO wake at all, for that agent, every time, until someone notices.** Your job: make a large room-count survivable, and make sure that if it ever *does* fail, it fails loudly instead of silently deleting an agent from the team.

**Why this matters now rather than later:** eight agents, each in many rooms, is exactly the shape the Meta-Meeting creates. **This is pre-existing on `main` — it was surfaced by the ACfr pagination lane and deliberately NOT folded into it** (route-don't-fold: a rider arrives with none of the review attention aimed at it).

### 2b. ⚠️ TWO FINDINGS THAT CHANGE THE SHAPE OF THE TRIP — added 2026-08-10, after the brief was first written

**(i) 🔴 THE EXISTING PAGINATION DOES NOT HELP HERE, AND §3 BELOW WILL POINT YOU AT IT ANYWAY.** `readThreadDigestRows` is **already** wrapped in `paginateAll` — and the `.in('thread_id', threadIds)` sits **INSIDE the `page` callback** (`digest/index.ts:126-136`), so **every page request re-sends the entire id list in the URL.** Paging bounds how many *rows* come back; the 414 is about how long the *request* is. **They are orthogonal axes, and the request fails on page one.** ⚠️ **So the instinct §3 encourages — "we have `paginate.ts`, extend it" — is a trap in its simplest form.** A correct fix almost certainly chunks the **id list** *and* paginates **rows within each chunk**; that is two dimensions, not one, and `paginateAll`'s ascending-cursor contract has to survive inside each chunk. **Establish this yourself before you design — it is the single highest-leverage thing to get right on day one.**

**(ii) The surface grows monotonically and never shrinks — so this is not "an agent in 370 live rooms."** `readEverMemberThreadIds` (`digest/index.ts:89-106`) reads `thread_subscriptions` with **no `dismissed_at` filter** (deliberate — ever-member visibility is by design) and **no state filter**; nothing in `src/` ever `DELETE`s a subscription row, and dormancy never reverses (Step 7 / `L12`). **Bounded, and deliberately NOT in scope** (confirm rather than assume, then leave them alone): `safety/kill.ts:74` and `wakes/capabilities.ts:99` take a fixed 2-element array; `scheduler/index.ts:364` takes `ACTIVE_AGENTS`; `scheduler/index.ts:410/422` take ids from queries already bounded by `.limit()`.
