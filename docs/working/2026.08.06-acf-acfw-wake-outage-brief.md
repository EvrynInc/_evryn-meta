## 1. The mission, in one paragraph

`evryn-team-runtime` is the autonomous harness for Evryn's 8 founding-team agents (ADR-050), **dormant by construction** until the Meta-Meeting. When the runtime composes an agent's wake it fetches that agent's rooms with a PostgREST `.in('thread_id', [...])` filter — **and that id list goes into the URL.** Past roughly **370 ids** the request exceeds the server's URL length limit and returns **HTTP 414**. **The throw escapes `composeWake`, which sits OUTSIDE `runWake`'s try/catch — so it is not a degraded wake, it is NO wake at all, for that agent, every time, until someone notices.** Your job: make a large room-count survivable, and make sure that if it ever *does* fail, it fails loudly instead of silently deleting an agent from the team.

**Why this matters now rather than later:** eight agents, each in many rooms, is exactly the shape the Meta-Meeting creates. **This is pre-existing on `main` — it was surfaced by the ACfr pagination lane and deliberately NOT folded into it** (route-don't-fold: a rider arrives with none of the review attention aimed at it).

## 3. ACf's design position — you may overrule it

**Two things need to be true, and they are separable:**

1. **A large room count must WORK.** The natural fix is to chunk the id list into batches comfortably under the URL limit and merge the results — the same shape as `src/db/paginate.ts`, which ACfr added yesterday for the row-ceiling problem. **Read that module first**; if it can be extended rather than paralleled, prefer that. ⚠️ **Chunking changes result assembly — make sure ordering and de-duplication survive it**, especially in the digest path where the composer expects a stable order.
2. **A composition failure must never silently delete an agent from the team.** Even fixed, this is a *class*: composition can throw for reasons nobody has thought of yet, and today any such throw yields no wake and no alert. **⇒ ACf's lean, which is the more valuable half of this trip: give the composition path the same treatment the boot path got — a loud, uniform failure.** The runtime already has the pattern (`src/safety/emergency.ts`, and `runWake`'s own park-and-ping). Whether the right shape is widening `runWake`'s try, a park record, an emergency alert, or some combination is **yours to decide** — but a silent no-wake is not an acceptable end state.

**The honest scope question, and I want your read on it:** fix (1) alone closes the known trigger; fix (2) closes the class. **ACf believes (2) is worth doing in this trip** because the whole lane's lesson this week is that *absences* are what hurt us and a silent outage is the purest absence there is. **If you disagree — if (2) is genuinely a separate trip — say so with your reasoning rather than quietly doing one or both.**
