## §5 — 🔴 THE BIGGEST DESIGN IDEA IN THIS LANE HAS NO STEP, NO OWNER, AND NO DESIGN PASS

**This is the finding Justin should care about most, and it is not a compaction casualty — it happened live.**

**The idea, called *the work record*:** the runtime keeps an **append-only ledger** of what each agent actually did in a room — the calls it made, what came back, and (this is the surprising part) **what it concluded** — and composes a bounded slice of that back into later wakes.

**Why it matters, in Justin's own framing:** the pain is that an agent re-investigates what it already ruled out. A session solves that by keeping everything, at the cost of freezing the agent's memory trunk. **A ledger solves it by keeping only the part that was actually lost — and unlike a session, it is *ours*, so we choose what to compose back.**

**The four load-bearing facts, all verified at source by `ACfsq` and recorded in `_evryn-meta/docs/research/2026.08.12-acfsq-team-runtime-sdk-sessions.md` (§4.3, §11, §13):**

1. **The agent's reasoning already reaches our runtime** — as thinking content on the message stream the wake loop iterates — **and the loop handles only the final `result` message, so every other message is received and silently discarded.** It is not unavailable. **It is arriving and being thrown away.**
2. **This is a second STORE, not a change to the scratchpad.** The scratchpad is agent-written, snapshot-semantics, **clobberable**. The work record is **runtime-written and structurally un-clobberable, because the agent has no verb that touches it.** An invariant, not a discipline.
3. ⭐ ***"Record everything, compose a little. A ledger you can query is not a layer you must carry."*** This is why it beats a session rather than merely costing less.
4. **Sizing: pointers and conclusions, never payloads.** For a file read, the content is not lost — the file is still there. What was destroyed is *that the agent read it and what it concluded*. Record the path, a hash, and the one-line conclusion. **Never the file body.**

- **Step 65** defers part of its own scope to *"the work-record design pass."*
- **Step 67** says the append-only job is *"meant to be carried by the accumulating work record."*

**Two Steps are leaning on a design pass that was never commissioned. It has no Step of its own** (highest filed is 67; this would be **68**), **no owner, and no scheduled design pass.**
