## 1 — The gap this closes, and why it is not just "write a pointer"

**Justin's question, 2026-08-18:** *"presumably we could spin DC as a main agent sometimes — would he be confused by what his agent def says?"*

AC0-37d answered it for **today**, correctly: a DC running as a **main agent** inside `evryn-dev-workspace` auto-loads that repo's `CLAUDE.md`, which *is* his real manual, so nothing is wrong. **That was a correct answer to a different question.**

🔴 **The problem is post-cutover, and nobody has designed it.** Step 5 turns that file into a redirect. From that moment:

- A **spawned** DC (agent type `dc`, from a session rooted in `_evryn-meta`) is fine — the harness hands him `dc.md` directly.
- A **main-agent** DC, working in `evryn-dev-workspace`, auto-loads **the redirect** — a stub. **Whether he recovers depends entirely on what that stub says**, and today the stub does not exist.

⚠️ **Second-order, and it is the part a plain pointer would miss:** each definition's front matter is written **wholly in spawned-as-subagent terms.** `dc.md` opens: *"The harness delivers it when you are spawned as agent type `dc` from a session rooted in `_evryn-meta`."* **A main-agent DC who follows the redirect and reads that sentence is being told something false about his own situation** on the first line of the file he was just sent to. He is not being spawned, there is no tagged brief coming, and nothing has been delivered to him.

⇒ **A redirect that only says "your manual moved" is insufficient. It has to serve the reader who arrives with NOTHING loaded.**

---

## 2 — The design, in four properties

The redirect has exactly one job: **get an agent from "I have a stub" to "I have my complete manual and I know which situation I am in," with no judgement calls.** Four properties make that work:

1. **Name the file, the path, and the requirement to read it IN FULL, from disk.** Not "see the agent definition" — the literal path, plus the canary to confirm.
2. **Distinguish the two arrival paths explicitly**, because the reader cannot tell which one applies without being told: *spawned as a type* (you already have it — this file is a signpost you passed) versus *running as a main agent here* (you have nothing — go read it now).
3. **Carry the hard rule forward.** The router's one hard rule — if your identity does not load, stop and report — has to survive in the redirect, because the redirect is now the only thing a main-agent reads before deciding what to do.
4. **Say what the repo still is.** These repos remain as working directories and archives; a redirect that reads like a tombstone invites someone to delete a repo that still holds mailbox files, build research and session docs.

⚠️ **What the redirect deliberately does NOT do: summarise the manual.** A redirect that paraphrases even a little becomes a fourth copy that drifts — which is the exact failure the cutover exists to end.
