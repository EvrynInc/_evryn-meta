> ### 🔴 READ THIS BEFORE HAZARD 2 — what "byte-identical" does and does NOT mean, and the specific landmine underneath it
>
> **Justin raised this and he was right to.** His question, paraphrased: *"you say everything must end up byte-identical — but is that even possible? Code running **within** a file is surely different from code **calling** another file. There are going to be choices made."*

> **The distinction that resolves it:** the byte-identity requirement is about the **runtime OUTPUT STRING** — the assembled system prompt sent to the model — **not about the code's shape.** You may split, rename, and re-import as freely as good design demands. Moving a function to another file does not change what `loadCommonPrefix()` *returns*. **So yes: choices get made, and that is fine. What may not change is the string.**
>
> **But his instinct points at a real landmine, and AC0 verified it at source.** `loadCommonPrefix()` doesn't take its content from anywhere in the code — it reads **files off disk**, and it locates them like this:
>
> ```ts
> const IDENTITY_DIR = join(import.meta.dirname, "../../identity");   // classify.ts:95
> ```
>
> **`import.meta.dirname` is the directory of THE MODULE ITSELF.** From `src/triage/classify.ts`, `../../identity` resolves to the repo's `identity/`. 🔴 **Move that code to a different directory DEPTH and the same literal silently resolves somewhere else.** `src/identity/compose.ts` still works (same depth); **`src/compose.ts` resolves outside the repo root; `src/triage/identity/compose.ts` resolves to `src/identity`.** Nothing about the code looks wrong at either site.
>
> **🔴 And here is why it is a landmine rather than a bug you'd notice:** `readIdentityDir` **does not throw on a missing directory.** It logs one line and **returns `""`** (`classify.ts:187–190`) — and `loadCommonPrefix` then does `parts.filter(p => p.length > 0)`, which **drops the empty part entirely.** So a wrong path doesn't crash and doesn't error. **Whole sections of Evryn's identity just quietly stop being in her prompt.** She gets measurably worse at her job, the cache prefix changes, the bill moves — and the only trace is a `console.log` nobody is reading.
>
> **⇒ Three things you must preserve exactly, none of which are visible from the function's signature:** (1) **the resolved path to `identity/`** — if your extraction changes the module's depth, make `IDENTITY_DIR` robust rather than re-counting `../`; (2) **the ordering** — `core.md` first, then directories in that literal sequence, each `.sort()`ed; (3) **the filters and the separator** — `.md` only, skip `_`-prefixed and `README.md`, honor the per-call exclusions (`reflection.md`, `operator.md`), and join with exactly `"\n\n---\n\n"` at both levels.
>
> **`tests/test-cache-byte-identity.ts` already exists** — AC0 confirmed it. ⚠️ **Check what it actually asserts before trusting it.** If it recomputes the prefix and compares it to itself, it will happily pass while the content silently empties. **It is only a real guard if it compares against a stored expected value or asserts a non-trivial length/section count. If it doesn't, making it discriminating is your first commit, before you move a single line.**

2. **🔴 `loadCommonPrefix()` must produce a BYTE-IDENTICAL string after extraction — this is a money property, not a style one.** Anthropic's prompt cache is prefix-based: a byte-identical system prompt across calls costs ~10% of a fresh one. That cached prefix is the difference, in Emma's runway numbers, between roughly six weeks and roughly two. `loadCommonPrefix` builds its string by globbing identity directories, sorting alphabetically, and joining with a specific separator — **change the ordering, the separator, the filter, or the join by one character and the cache silently misses and costs jump.** Nothing will fail. Nothing will alert. The bill just goes up. **Assert byte-identity explicitly in a test** — that test is the single most valuable artifact of this deliverable.
