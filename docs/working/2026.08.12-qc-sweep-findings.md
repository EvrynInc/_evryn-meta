## 1. The question this sweep asked — and why it is different from a review

Not *"is this code correct?"* but ***"if this code were broken, would anything actually notice?"***

**A green test suite tells you the tests did not complain. It does not tell you they *would* complain if the code broke.** Those two feel identical and are not. The only way to tell them apart is to break the code on purpose and watch the verdict.

This matters here for a specific, documented reason. The Code Atlas (`evryn-backend/docs/atlas/`) tags every invariant it records as **STRUCTURAL** (the code makes violation impossible) or **INSTRUCTIONAL** (a comment or convention asks nicely). That tag is the Atlas's most valuable content — it tells a reader whether they are protected or merely advised. But the Atlas's own verification boundary states plainly that **no agent on the pass that produced it read the test tree, and nothing in it was executed**. Every "pinned by a test" claim in it was therefore unverified.

**This sweep is the execution pass.** Expect some invariants tagged STRUCTURAL to turn out unprotected — that is the sweep succeeding, not failing.

## 2. How to trust this document — the instrument was verified first

**Everything below depends on one thing: that `npm test` reports failure when there is failure.** If the runner can print a green verdict over a real failure, every result in this file is fiction. So the first act of the sweep was to test the runner itself, not the runtime.

`scripts/run-tests.ts:478` carries a guard whose own comment claims to be load-bearing:

```ts
} else if (!opts.live && failed === 0 && detectNeedsLiveAtRuntime(out, exitCode)) {
```

The comment asserts that deleting `failed === 0` makes a genuinely failing suite report `NEEDS-LIVE` — which is not counted as a failure — so **the run prints `ALL GREEN` and exits 0 with real failures in it.**

**That claim was tested, and it is true.** A probe suite was planted emitting both signals the runner must arbitrate: a real `FAIL` assertion line (exit 1) *and* a non-assertion detail line containing a `.invalid` host (which is what the runner's `NETWORK_REACH` pattern matches).

| # | State of the guard | Reported outcome | Exit code |
|---|---|---|--:|
| 1 | intact | `FAIL — 1 assertion(s) failed` | **1** ✅ |
| 2 | `failed === 0 &&` removed | `NEEDS-LIVE` → **`=== ALL GREEN ===`** | **0** 🔴 |
| 3 | restored | `FAIL` | **1** ✅ |

Mutation proven applied by string count (target occurrences 1 → 0); restore proven by an empty `git diff`.

⇒ **The guard is genuinely load-bearing, and it works. The instrument is sound, so the verdicts below are worth what they claim.**

**One nuance worth keeping:** even in the broken state the summary still printed `assertions 1 (0 passed, 1 failed)`. A human reading the tally could catch it — but the *verdict word* and the *exit code* both said healthy, and those are what a CI gate and an automated reader consume. The guard is not redundant.

## 3. Method, and its limits

**Per mutation:** regenerate the dependency map → take a baseline in the same run → change exactly one line → **prove the mutation applied** → run the full suite → restore → confirm clean.

**Every verdict is one of three, and the third is never collapsed into the second:**

| Verdict | Meaning |
|---|---|
| **RED** | Something went red. The invariant is genuinely protected. |
| **GREEN** | Nothing noticed. It is **not** protected, whatever the Atlas tags it. |
| **INCONCLUSIVE** | Went green, **but** a suite that does not run in the default mode imports the mutated file, so a guard may exist in a suite that never executed. |

### 3a. 🔴 The limits of this sweep — read these before trusting a GREEN

1. **13 suites never ran.** The runner's default (SAFE) mode skips every suite that declares a live-DB dependency, plus 2 more relabelled at runtime. **`--live` was not used and was not authorised** — it spends real Anthropic money and writes to a real database, which is Justin's call and he was asleep. The 15 excluded suites are:
   `run-fixtures` · `test-approval-flow` · `test-care-eligible-users` · `test-clustering-dev` · `test-conversation` · `test-emailmgr-updated-at` · `test-evryn-initiated-placeholder` · `test-execute-approval-transport` · `test-haiku-screen-dev` · `test-messages-ordering` · `test-pipeline-approval` · `test-processing-stuck` · `test-step57-dev` · `smoke-test` · `test-query`.
   ⇒ **Everything marked INCONCLUSIVE is a question this sweep could not close without spending money.** They are batched for Justin in §7.
2. 🔴 **`npm test` does not typecheck.** `tsx` strips types without checking them. ⇒ **Any invariant that is STRUCTURAL "because the compiler enforces it" is invisible to the default gate.** `npm run typecheck` is a separate command against a separate config (`tsconfig.tests.json`). Lanes were instructed to run both where a mutation could be a type error.
3. **A filtered run is not a verdict.** `npm test -- --filter X` is fast triage only. A filtered **RED** is conclusive; a filtered **GREEN** is worthless — and one filter this night matched **zero** suites and printed `ALL GREEN` having executed nothing at all.
4. **This sweep measured coverage, not correctness.** A RED verdict says something noticed the break. It does not say the code is right, or that the test asserts the right thing.
5. **The identity half (`identity/**`, 11 files, 1,378 lines) was not mutation-tested.** Its guarantees are instructional by construction — no test can go red on a prompt wording change — so mutation is the wrong instrument there.

## 4. Head-level findings — established directly, not by a lane

### 4.1 🔴 The Atlas states a false byte-level fact about the halt sentinel — and the code is fine

`evryn-backend/docs/atlas/07-safety.md:330-333` documents `BREAKER_HALT_SIGNAL` as **space**-delimited, twice, with emphasis (*"note the leading and trailing space"*, *"its surrounding spaces are significant"*).

**They are not spaces. They are NUL bytes (U+0000).** Byte-scanned independently by three agents. The literal's character codes are:

```
[0, 95,95, 69,86,82,89,78, 95, 66,82,69,65,75,69,82, 95, 72,65,76,84, 95,95, 0]
 ^NUL  __      E V R Y N    _   B  R  E  A  K  E  R   _   H  A  L  T   __  ^NUL
```

**How the error happened is the important part, because it is the exact failure mode this sweep exists to catch:** the Atlas author read the file through a text-rendering path, **the NULs rendered as spaces**, and it was written down as fact. Two further agents reproduced the same misreading before a byte scan settled it.

🔑 **But the code is not the defect — the documentation is.** `src/safety/halt-signal.ts`'s own comment says the sentinel was *"chosen to be something Evryn would never produce as a real text result"* — and a NUL byte delivers exactly that, far more strongly than a space would. **The NUL delimiters look deliberate and good.** What is missing is that the comment states the *intent* and never names the *mechanism*, which is precisely how three readers got it wrong.

⚠️ **The risk this creates:** someone "tidying" those NULs into spaces, believing the Atlas — a change that would be **invisible in `git diff`** (see §4.2). **This should be routed as a docs-and-comment fix, never as "remove the NULs."**

### 4.2 Two corrections to how the NUL-byte files have been described

A byte scan of all 148 `.ts`/`.md`/`.json` files under `src/`, `scripts/`, `identity/` and `tests/` found **exactly two files containing NUL bytes.**

1. 🔴 **`scripts/dependency-map.ts`'s NUL is not a defect — it is a deliberate composite-key separator.** At line 443: `` const key = `${rel}\0${target}`; `` — a NUL is the idiomatic separator that cannot collide with a filesystem path. **`_evryn-meta/docs/current-state.md:54` (SPRINT Step 106) lumps this file together with `halt-signal.ts` as one item ("two files that contain a NUL byte"). They are not one item**, and routing them together would send someone to "fix" correct code.
2. **"Invisible to every grep" is overstated; "opaque to `git diff`" is exact.** Measured: `grep -c` found the sentinel string fine (returned 1). But `git diff` reports `Binary files … differ`, `Bin 2060 -> 2062 bytes`, **0 insertions / 0 deletions**. ⇒ **The standard applied-proof step — "show me the changed line in the diff" — is genuinely broken for `halt-signal.ts`**, and any change to it, including an accidental one, will not appear as a readable diff.

### 4.3 `docs/dependency-map.json` was stale at this SHA, and the staleness is scoped

Regenerated from a pristine tree: committed **337 internal edges / 77 test files / 18,578 test lines** → fresh **361 / 78 / 19,234**. The committed artifact is missing `tests/env-seed.ts` and 24 `value` edges; it landed on 2026-08-10 without regeneration.

**The scoping matters and limits the blast radius:** the drift is **entirely in the `tests/` half** (each suite gained an `env-seed` edge; `test-cache-byte-identity.ts` also grew 81 → 454 lines from the Step-101 rewrite). **The `src/`-side reverse index is unchanged** (45 files, 20,089 lines).

⇒ Lookups of *"who imports X in `src/`"* were never at risk. What was stale is **§8 test-coupling** — which is exactly the table used to decide whether a GREEN result is really INCONCLUSIVE. **Every lane regenerated its own copy before triaging.** The committed artifact should be regenerated on `main`; that is routed, not done here.

### 4.4 Methodology hazards this sweep hit, worth carrying forward

- **CRLF line endings broke a mutation in three separate lanes**, every one caught only by the applied-proof step — and in one case a false green would have been recorded as a real vulnerability. **Normalise line endings in any string matching used to apply a mutation.**
- **A filter that matches zero suites prints `ALL GREEN` having executed nothing.** Always check the reported selected-suite count.

### 5.1 M6 — safety, security, bootstrap · **35 mutations: 25 RED · 9 GREEN · 1 INCONCLUSIVE**

🔑 **This lane produced the sweep's calibration result: it found an undisclosed known-positive cold, by execution.**

**The finding: several guards silently stop guarding when their env var is set to an EMPTY STRING.** The runtime reads these knobs as `parseInt(process.env.X ?? "default", 10)`, and **`??` does not catch `""`** — only `undefined`/`null`. So an *unset* variable is safe, but a variable that is **created and then cleared** (an ordinary Railway operation) yields `NaN`, and every comparison against `NaN` is `false`.

Demonstrated by execution, not inferred:

- **5,000 identical loop signatures fail to trip the loop-signature detector.**
- **5,000 attempts fail to trip the velocity ceiling.**
- **A 40,000-character exfiltration URL is allowed** past the web guard's length caps.
- **And the guard keeps looking alive** — the SSRF and scheme checks still deny normally, so the logs show a functioning guard.

⇒ **The two automated defences against runaway Anthropic spend, and the exfil-shape half of the egress guard, can be silently disabled by an operator action that looks like housekeeping.** This is the same defect class `src/config.ts:512-556` was written to close; these sites were never routed through the shared bounded parser.

### 5.2 M4 — triage bookkeeping and persistence · **13 mutations: 3 not protected**

**A security surface, found by execution:** the **anti-enumeration projection** in `src/db/users.ts` can be replaced with a spread and **the suite stays fully green** — because the test guarding it feeds only clean rows, so the widened projection has nothing extra to leak in the fixture.

⇒ **Operationally: a widened projection turns the anti-enumeration name resolver into a PII dumper, with nothing failing.** The projection — not the hand-maintained column list — is the property actually protecting that surface, and it is unguarded.

Two more, with their operational meaning:

- **An unrestricted `backfillThreadScope`** repoints an already-established thread's scope. Because `getThreadScope` performs no `.order()`, the result then **resolves nondeterministically** — surfacing **the wrong user's profile in an operator turn**, in exactly the channel ADR-030 exists to isolate.
- **The `updateEmailmgrItem` hole** means that neither the existing silent-metadata-loss defect **nor any future regression of it** can be caught by the `npm test` that CI and every agent actually runs.

## 6. Standing review patterns this sweep earned

Proposed for the **Patterns This Role Watches For** section of `evryn-quality/CLAUDE.md`. **These require Justin's approval before an AC writes them in** — they are proposals, not entries.

1. **A projection or filter tested with an input that lacks the very thing it excludes.** *Trigger:* a test pinning a guard whose job is to *withhold* something, where the fixture contains nothing to withhold. *Failure:* the guard can be widened or removed and the suite stays green, because the fixture could never have demonstrated the leak. *Move:* feed the excluded thing in — a row carrying the firewalled column, a payload containing the denied shape — and confirm the verdict flips. *Seen 1x.*
2. **A test helper that re-implements the runtime guard the test claims to cover.** *Trigger:* a test whose header says it pins a specific runtime line, whose body defines a local `simulate*`/`replay*` helper inlining that logic instead of calling the real function. *Failure:* delete the runtime guard and the suite stays fully green, while the file's own header asserts the case is covered. *Move:* delete the real line and re-run before believing the coverage; drive the real entry point, exporting it with injected dependencies if necessary. **Seen 2x.**
3. **Bump an existing entry: *"a test whose parameters sit on the safe side of the threshold it claims to test"* → Seen 2x.** M4's first finding is a recurrence of it.

**A fourth, proposed by the sweep lead from §4.1:** **a documentation claim about a whitespace- or delimiter-sensitive literal, made without reading the bytes.** *Trigger:* any doc, comment or brief asserting that a literal's delimiters are spaces, tabs, or newlines. *Failure:* text-rendering paths display NUL, non-breaking space and several control characters identically to a space, so the claim is written down as fact and propagates — three agents made the identical error on one literal tonight. *Move:* read the file as a `Buffer` and print character codes before asserting anything about a delimiter; and treat `git diff` as unreliable on any file containing a control byte, because it degrades to `Binary files differ`.
