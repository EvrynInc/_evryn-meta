## Bounced, or found wrong in the brief

**Nothing blocked the work.** Six things a reader should know, each decided in the open:
1. **A `begin` with no `--incoming` exits 2, not 1.** Exit 2 is the class `begin` already uses for a missing `--agent` or `--handoff` (a usage refusal). The message starts `REFUSED:` and names both forms. The tests assert only a non-zero exit, so changing it to 1 would take one argument.
2. **Item 2: "carried forward" is now checked before the path is resolved.** An incoming entry the outgoing list names passes whatever its state, so a path that resolves nowhere but has been carried forward does not FAIL. **Why:** "committed **or** carried forward" is the obligation, and an honest seat copying its predecessor's list verbatim should not FAIL for its predecessor's path form. Historical mode gives the same result either way, because it never failed on an unresolvable path.
3. **What "resolves nowhere" means:** no repo holds the path. The cases are a directory that doesn't exist, a first segment that isn't a repo name with no match in the handoff's repo, and a handoff that sits in no repo. **A missing file inside a real repo still reads as committed** (`git status` is clean for it). That behaviour is unchanged, and I left it, because nothing uncommitted exists there to lose.
4. **The repo-name rule follows the writing protocol to the letter.** A seat working in a worktree such as `_evryn-meta-packout-guard` that lists `_evryn-meta/docs/x.md` resolves to the main checkout `_evryn-meta`, not to its worktree. That is what the protocol's form means. Worth a line in step 6's text.
5. **Seen and not fixed, because it is outside item 2's scope and was not introduced by this trip:** the incoming lists `shared/x.md` bare while the outgoing carries it as `evryn-team-workspace/shared/x.md`. `named()` matches by suffix in one direction only, so this carry is not recognised, and an uncommitted `x.md` FAILs an honest seat. **For the v1.1 queue:** compare the two resolved paths.
6. **Item 6, the report half:** `check` writes the report through Node's `fs`, not through a tool call, so the report enters C10's written set only when the seat writes it by hand. The item 6 test simulates exactly that. The handoff half is the live case from field test 1. **I have not seen Adm Soren 11.20 pm's packout**, so I can't say whether items 6 and 7 alone turn its C10 to PASS.
