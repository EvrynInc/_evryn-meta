# 6 · The four answers ACv owed him — drafted, ready to deliver

## A. 🔴 What is actually causing the broken-checker pattern

**Justin's question:** *"That's four in one day, and they're all the same shape… what is causing this? We need to get to the bottom of it and fix it."* **(It became five.)**

**The five:** ACv's Map validator reported 16 mismatches that did not exist · an audit's `grep -P` errored on every call and "established" that 53 files had no references · `scan-control-chars.js` printed `CLEAN` having scanned zero files · ACv's `grep -E 'a\|b'` returned 0 hits on strings that were present *(inside `-E`, `\|` is a literal pipe, not "or")* · QC's mutation driver nearly mutated the wrong line because its search text appeared twice.

**They look like five different bugs. They are one.**

🔑 **THE CAUSE: in every one of these tools, "I found no problems" and "I did not actually look" produce THE SAME OUTPUT.** The success signal is an *absence* — no findings, no errors, a clean exit. **So any failure that produces no output is indistinguishable from success**, and it is indistinguishable *by construction*, not by accident.

**The CEO-altitude version:** *a smoke detector with a dead battery and a smoke detector in a room with no smoke both sit there perfectly silent.* You cannot tell them apart by listening. **You need it to chirp — "I'm on, I checked, nothing" — or its silence tells you nothing at all.**

⚠️ **And the part that rules out the obvious fix: this is not carelessness.** Four of the five were written by careful agents **who had just been discussing this exact failure class**, one of them in the same hour. ⇒ **"Be more careful" cannot work. The fix has to be structural.**

**✅ THE FIX — one rule, cheap, and it closes all five:**

> **Every check must report WHAT IT EXAMINED, not only what it found.**
> `examined 40 nodes · 0 problems` — not `0 problems`.

**A zero-examination becomes visible instead of invisible.** ACv has been doing this since — including a control line naming a string known to be absent, so a checker that matches *nothing* cannot come back looking clean. **And QC's mutation driver already embodies the same principle from the other side: it REFUSES on an ambiguous match rather than silently taking the first one.**

⇒ **Two rules worth promoting into DC's and QC's manuals** *(ACv did not do this — it is a source-of-truth edit and Justin's call)*: **(1) a check reports its examined-count beside its verdict; (2) a tool refuses on ambiguity rather than guessing.**

## B. The maintenance model, in plain English

**Justin's question:** who keeps the Map current, what triggers it, and how does it nag *just enough*?

**The Map holds two kinds of information that go stale at completely different speeds:**
- **Facts** — how big files are, what's switched on, what's deployed. These change **every time anyone ships.**
- **Shape** — which boxes exist and how they relate. This changes **rarely**, only when the product design changes.

🔑 **Treating them the same is what would bog everyone down.** Almost everything that goes stale is *facts* — and **facts do not need a human at all.**

**So, four pieces:**
1. **Facts refresh by script.** Nobody does anything.
2. **Shape gets checked only when the code ACTUALLY MOVES** — and we can detect that automatically. We already have a tool that produces a byte-identical result when nothing has changed, so **any difference means something genuinely moved.**
3. **The Map tells on itself.** It stores a fingerprint of the code it was drawn against; when they diverge it shows a banner **naming the files that moved.** You see it when you open the Map — exactly when it matters.
4. **Don't create a new chore.** There is already a rule: *"if you changed the runtime's shape, update the Code Atlas."* **Make it "…update the Atlas AND the Map."** One rule, one moment, done by whoever moved the code — because they are the only one who knows what moved.

**Nagging is by age:** amber when it diverges, red with a day count once it has been stale over a week. *A check that never nags lets the Map rot; one that nags daily gets ignored.*

⚠️ **Deliberately rejected: a hand-maintained "last updated" line.** That is the exact shape that has rotted here before. **The fingerprint computes itself.**

**→ The ask: approve this shape and I build it. It is real work and I would rather build the agreed version once.**
