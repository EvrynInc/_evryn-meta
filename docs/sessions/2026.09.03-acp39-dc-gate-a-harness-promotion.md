## 3 · 🔴 The sequencing trap — getting this wrong arms a money-spending test in the default gate

**Step 1 of the spec renames the files off the `_` prefix. Step 5 adds a `RUN_LIVE_DB_TESTS=dev` opt-in gate.**

🔴 **These must land together, and step 5 must not be deferred.** The `_` prefix is what currently keeps these files out of the test runner. **Rename them without the opt-in gate and the harness becomes a suite that the default `npm test` will pick up and run — which drives real Opus calls and writes to a database, on every future test run, forever, with nobody having chosen that.**

## 5 · The task

**Execute the promotion spec at `evryn-backend/docs/gate-b-plan.md` §7.1**, with the §7.2 and §7.3 defects folded in. In summary — **but read §7 yourself; this list is an index, not a substitute:**

1. **Rename off the `_` prefix** — and **add the `RUN_LIVE_DB_TESTS=dev` opt-in gate in the same change** (see §3 above; this is not optional).
2. **Adopt the house live-DB idiom** — `bootstrapTestEnv()` first, then *dynamically* import config and db. All four files currently import `config` statically, which forces a real `.env`.
3. **Preserve the existing `assertNotProd()` calls** — do not reimplement or remove them. Two barriers is the intended posture.
4. **Never import `tests/env-seed.ts`** into a live-DB path.
5. **Fix the two silent-failure traps (§7.2):** the re-run that silently re-prints stale results, and the meaningless table produced when clustering is on.
6. **Fix the grading gaps (§7.3):** the two ③ verdicts with no branch (`handled_by_gatekeeper`, `not_a_candidate`), and the `original_from_user_id` expectation, which changed meaning at ③ so that `null` is now *correct* in cases the reviewer would read as a defect.
7. **Replace the hardcoded UUID** in `_gate-a-review.ts` with a lookup by the seeder's stable natural key, `systemtest@evryn.ai` (§7.4). **A lookup fails loudly; a stale ID file returns zero rows and prints a clean report.**

**Also resolve, and report which is right:** `_gate-a-review.ts` says fixture a13 should be absent while `_gate-a-times.ts` queries for it (§7.5.4). Nobody has determined which is correct.
