### Q4-1 · BLOCKER (honest) · C7 against packout step 6

**What the code does.** `checks.mjs` C7 (`:261-274`) is built to spec line 58: *"the incoming handoff Read to its canary after `begin`, and that text equals the file as it stands now."*
- `incomingText` is read from the path the `begin` call named, at `check` (or `verify`) time.
- If that path is gone, C7 returns `FAIL … not readable now`. Otherwise `equalsFile(lastWhole, incomingText)` must match line for line.

**What the protocol tells an honest seat to do.**
- Packout step 4 re-reads the incoming whole, which satisfies C7.
- **Step 6 then disposes of that same file** (`packout-protocol.md:156-158`, `lock-protocol.md` step 10). Every disposition changes it:
  - **retire** = archive it (a move);
  - **supersede** = archive it and add `SUPERSEDED BY:` at the top;
  - **hold** = add a `HELD-SESSION-DOC` banner;
  - **carry** = bring it fully current (an edit).
- Step 1 also allows exactly one edit to a predecessor's handoff: marking it SUPERSEDED.
- Step 7 runs `check` after all of this.

**Probes (`probes-3.txt`):**
- **A** (SUPERSEDED banner after the re-read) → `C7=FAIL (… line 1 differs (read "# Incoming handoff" vs now "**SUPERSEDED BY:** …"))`, exit 1.
- **A2** (the same, plus one more whole re-read after the banner) → C7 PASS. In-place edits are therefore recoverable, but only by a seat that knows to re-read *again* after step 6.
- **B** (HELD banner) → C7 FAIL, same message.
- **C** (archived by `git mv` under its own date, name unchanged, per lock step 10) → `C7=FAIL (the incoming handoff … is not readable now)`. **No re-read can fix this:** C7 only looks at the old path.
- **D** (a clean PASS, then the predecessor banners its incoming before the successor's `verify`) → `VERIFY FAIL C7: report says PASS, re-run says FAIL`.

**Live evidence that seats do this (by script; numbers and paths only):**
- Admiral Soren 1.19 pm (`dacfb635`, packout window from row 760) **Edited its incoming handoff at row 920 (08:43)**. Its only reads of that file were rows 58 (a `sed`) and 480 (Read 60–124), both before it.
- `evryn-team-workspace` has **40 commits since 11/06** whose diff adds "SUPERSEDED" to a `*handoff*` file (`git log -S`).
- Zero handoffs were renamed there in that window: team seats banner in place. AC lanes archive by `git mv` (lock step 10), which is shape C.

**Why the stop rule puts this on the blocker side.** C7 is a v1 check, and this is a false FAIL on an honest packout that followed the protocol in its own order. It is D3's check failing the seats D3 protects. **Neither real top-level packout hit it:** Soren 2's incoming is still unbannered at its original path, and AC-PG's incoming is the living brief in `_evryn-meta`'s main folder, unchanged since. That is luck of order, not design.

**Fix sketches (the Captain's design call):**
- **(a)** C7 keeps "Read whole after `begin`, to its canary" and drops "equals the file now" **for the incoming only**: the incoming is a predecessor's file that the seat is *supposed* to change in step 6. C8 keeps "now" for the outgoing, where it matters.
- **(b)** Keep "now", and tolerate step 6's specific changes: added banner lines at the top, or the file moved (follow it with `git log --follow --name-only`).
- **(c)** Text only: step 6 before step 4, and never archive the incoming by move during the packout (the successor archives it after `verify`). This is the weakest option, because it is a rule to remember.
- **The test that must fail without the fix:** probe A and probe C as suite tests, plus a mutation row.
