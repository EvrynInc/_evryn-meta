## 3 · 🔴 One finding that may be live in production — for Soren before anything else

**ACT-18's 2026-09-10 question, checked at the code and the SDK's own documentation (2026-11-17). Not executed.**

- **The SDK's rule.** `@anthropic-ai/claude-agent-sdk` **0.2.119** (installed; `package.json` declares `^0.2.119`), `sdk.d.ts`: *"When omitted, all sources are loaded (matches CLI defaults) … Must include `'project'` to load CLAUDE.md files"*, and separately *"`query()` … loads all sources when this is omitted."*
- **Neither call site passes it.** Evryn's `query()` (`src/triage/classify.ts`, the `for await (const message of query({` in `runEvrynQuery`) and the Haiku screen's (`src/triage/haiku-screen.ts`, `defaultRunQuery`) set no `settingSources` and no `cwd` — so the working directory is the process's.
- **Production puts the file there.** The `Dockerfile` is `WORKDIR /app` … `COPY . .` and **no `.dockerignore` is tracked** — so `/app/CLAUDE.md` and `/app/.claude/settings.json` ship in the image, in the working directory.
- ⇒ **Very likely, every Evryn query and every Haiku screen in production receives `evryn-backend/CLAUDE.md` in context** — a file that opens *"Stop. If you're here to build, do not build here,"* describes an operator "load Evryn" ritual, and lists internal pointers including the Hub (`_evryn-meta/docs/hub/roadmap.md`), which `BUILD-EVRYN-MVP.md` says Evryn must never access ("she cannot access the Hub or any internal strategy docs"). **She cannot read those paths** (her built-ins are only `WebFetch`/`WebSearch`; checked `allowedTools`), so this is **instruction-and-disclosure contamination of her context, not a file-read exposure.** `.claude/settings.json` carries only `permissions` (no hooks), inert under `bypassPermissions`.
- ⚠️ **ARCHITECTURE asserts the opposite** — Identity Composition: *"No `settingSources`, no filesystem-based config loading. Full control over every byte in the prompt."* **That is a design claim the runtime does not enforce.** It also breaks the byte-identical cache property the same section relies on, in a way no test would see.
- **What would settle it:** one captured live system prompt, or one DEV query with `settingSources: []` versus omitted. **The one-line fix** (`settingSources: []` at both sites) is a runtime change → DC+QC, and it **changes Evryn's prompt**, so it wants a live check.
- **Why it is in Soren's lane:** it is identity-integrity rather than user-data privacy, but it sits on the same "what is in Evryn's context" surface as T-101 fixes 1–3, and it is cheap. **OPEN for Soren:** fold into T-101, or its own small lane.
