## §7 — B4 in detail: the answer to ACP's cross-runtime security ask

**ACP's question: does `evryn-team-runtime` spawn any child process with a token, key, URI or password in its ARGUMENTS?**

**Answer: YES — the class is PRESENT. But the specific failure ACP named is already CLOSED, and a different residual remains.**

- **The two production spawn sites** are `src/boot/workspace.ts:78` and `src/composer/index.ts:124`, both `execFileAsync('git', args, …)`. `composer/index.ts:124` is `['-C', repoPath, 'rev-parse', 'HEAD']` — **no secret.**
- 🔴 **`workspace.ts` DOES put a credential in argv.** `authUrl()` (`:37-45`) builds `https://x-access-token:<token>@<host>/…` and that string is passed as an element of `args`.
- ✅ **The error-leak half — ACP's actual class — is closed by construction.** Every git invocation funnels through one wrapper, `git()` (`:72-87`), which catches the rejection and runs `redactToken()` over **both** `e.message` (which carries argv) **and** `e.stderr` (git echoes the remote URL) before anything is thrown or logged. `redactToken` (`:52-63`) has a second, token-independent pass that collapses **any** `https://user:secret@host` userinfo — so a rotated or differently-shaped credential still cannot leak. The token is never written to `.git/config`; the on-disk `origin` stays token-free.
- ⚠️ **The residual, already known and documented in-file at `:41-43`:** the tokenized URL is visible in the git process's **argv for the command's lifetime** — `/proc/<pid>/cmdline`-class exposure on a shared host. Logged as an accepted Phase-1 residual (QC finding 3) with a named eventual hardening: **a git credential-helper.** ⇒ **That is a different threat model from ACP's** (local process inspection, not an error string), and it is the one still open.

**Instrument disclosure:** the two-site completeness claim rests on `git grep -n -E "spawnSync|spawn\(|execFile|execFileSync|execSync|exec\(|child_process|node:child_process" -- src`, run **with a known-hitting control** to prove the search executed — **the array form is covered.** The *content* claims above come from a full read of `workspace.ts:16-130`. **A grep locates; it does not conclude — treat the completeness half accordingly.**

🔑 **AND A GAP THIS OPENED IN OUR OWN TRACKER: SPRINT Step 76 names both these sites for *bare-name executable resolution* and is SILENT that one of them carries a credential in argv.** The Step frames them as "strictly weaker than the npx class — no shell, no registry fetch," which is true of the PATH hazard and misses the sensitive half at the same line. **Owed: widen Step 76, or file the credential residual as its own Step.**
