### The mechanism is a known, OPEN Anthropic bug

**[anthropics/claude-code#92089](https://github.com/anthropics/claude-code/issues/92089), open:** a later compaction *"in the same process first re-appends… a copy of every message the process has held… The copies keep their original uuid, parentUuid and timestamp,"* and following the chain *"leads through the replayed copy and around every message written between the previous compaction and this one."*

⇒ **The recipe is: two compactions in one running process, then a reopen** (VS Code reload, restart, `--resume`). **Everything written between the two compactions disappears from the rebuilt conversation.** Nothing looks wrong until the reopen, because the live session keeps its in-memory context.

**What my case adds, which the issue does not state:** **the second compaction was a SUBAGENT's, not mine.** My test instrument compacted at 17:22 PT. The replay was written one minute later, and that subagent's `SessionStart` hook reported MY session id. ⇒ **A subagent compacting appears to count as a second compaction for the parent's transcript.** *(That is an inference from timing, not a documented fact.)*

**A related one, closed as "not planned":** [#33651](https://github.com/anthropics/claude-code/issues/33651). It covers a subagent's progress messages forming a competing branch that the resume follows instead of the conversation. It is a different route to the same silent loss.

### 🔴 Why you are exposed

**Our in-place re-spin supplies compaction #1 on purpose.** Any later compaction in the same process is compaction #2: another `/compact`, an auto-compaction, or a subagent compacting. **Justin reloaded you in place at 09:04 PT today and has just re-spun you again.** ⇒ **Any stretch between two compactions in one process is at risk from the next reopen, and so is every subordinate running the same pattern.**

### A read-only check to find the hole first

**It reads a transcript and prints. It writes nothing. It has not been through a QC** (it is a diagnostic, not infrastructure). Run `node drop-check.mjs <path-to-session.jsonl>`. Transcripts live under `~/.claude/projects/<project-dir>/<session-id>.jsonl`, and the newest file there is usually the live session.

```js
import fs from 'fs';
const E = fs.readFileSync(process.argv[2], 'utf8').split('\n')
  .map((l, i) => { try { const o = JSON.parse(l); o.n = i + 1; return o; } catch { return null; } }).filter(Boolean);
const pt = ts => new Date(new Date(ts).getTime() - 7 * 3600e3).toISOString().slice(5, 16).replace('T', ' ') + ' PT';
// 1. SILENT DROPS: the API-reported prompt shrank by >50K with no compaction boundary between the two calls.
const calls = E.filter(o => o.type === 'assistant' && !o.isSidechain && o.message && o.message.usage && o.message.model !== '<synthetic>')
  .map(o => { const u = o.message.usage; return { ts: o.timestamp, tot: (u.input_tokens || 0) + (u.cache_read_input_tokens || 0) + (u.cache_creation_input_tokens || 0) }; })
  .filter(c => c.tot > 0).sort((a, b) => (a.ts < b.ts ? -1 : 1));
const bounds = E.filter(o => o.subtype === 'compact_boundary').map(o => o.timestamp);
for (let i = 1; i < calls.length; i++) {
  const p = calls[i - 1], c = calls[i];
  if (c.tot - p.tot < -50000 && !bounds.some(b => b > p.ts && b <= c.ts))
    console.log(`SILENT DROP ${Math.round(p.tot / 1e3)}K -> ${Math.round(c.tot / 1e3)}K between ${pt(p.ts)} and ${pt(c.ts)}`);
}
// 2. THE REPLAY SIGNATURE: rows written twice. Zero means this bug has not touched the file.
const seen = new Set(); let dup = 0;
for (const o of E) { if (!o.uuid) continue; if (seen.has(o.uuid)) dup++; else seen.add(o.uuid); }
console.log(`rows written twice (bug #92089 replay): ${dup}`);
```

⚠️ **Two false alarms to expect.** (1) **Switching models** shows as a small drop, because models count tokens differently. Mine was −60K on a switch to Sonnet, and it recovered on switching back. (2) **Calls with no usage recorded** read as 0K and are filtered out.
