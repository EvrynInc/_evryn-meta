## 5 · Findings in detail

### Q3-1 · BLOCKER · The seat-writable state folder buys a false C5 PASS, and `verify` confirms it
- **What the code does:** C3 and C5 count an extract when (a) a Bash call's command text matches `packout\.mjs["']?\s+(begin|sweep)` and its output names the path (`anchors()`, `packout.mjs` 181–203), and (b) `state.json` lists it with a `fileSha` equal to the file's own sha. They then require a Read to the marker and that the read text equals the file (`checks.mjs` 162–175). **Nothing ties the extract's body to the transcript.**
- **Evidence (`probes-c.txt`, STATE-i):**
  1. In the good packout, the seat ran sweep 2 (an honest anchor) but **never Read it**, so C5 FAILs.
  2. The seat then overwrote `sweep-2.txt` with `x` plus a valid marker (`END OF SESSION TEXT · 1 lines · sha256 <sha12("x\n")>`), set that entry's `N=1` and `fileSha` in `state.json`, and Read the 2-line file.
  3. → `check` exit 0, **C5 PASS** ("extract sweep-2.txt (1 lines) made at 25, Read to its marker … after the handoff's first write"), and **`VERIFY PASS`, exit 0**.
- **STATE-ii (no sweep at all):** `echo "node packout.mjs sweep" >/dev/null; echo "sweep 9: <path> (1 lines + marker"` plus a hand-added state entry gives **C5 PASS and VERIFY PASS, exit 0**.
- **No transcript row is fabricated.** These are a Write and an Edit, which a real seat would make with ordinary tools.
- **Why BLOCKER, and the honest case against:** it is the same kind of move as F2 (state planted in the report, ruled BLOCKER), and it falsifies the review §3 item 10(c) claim that *"editing the state file or the report … buys nothing"* (quoted by QC1). Like N11, it is deliberate forgery. **Unlike N11, it needs no hand-built JSONL:** two edits to small files. The AC may rule it a residual beside N11; if so, it should be named in the README, not discovered.
- **Fix sketch (any one closes most of it):**
  - **(a)** C3 and C5 re-derive the extract from the transcript, `buildExtract` over the rows up to the anchor. Accept when the marker's sha equals the rebuild at some prefix ≤ the anchor row, as QC2's `realtop.mjs` did.
  - **(b)** A check that FAILs when the session wrote anything into its own state folder (Edit, Write or a Bash target).
  - **(c)** The anchor requires the segment's first word to be `node` invoking a path ending `packout.mjs`, as `launchSegment` does for launches.

### Q3-2 · BLOCKER · The downgrade is still forgeable on the same machine: the session id it trusts is seat-written
- **What the code does:** `cmdVerify` downgrades when `findTranscript(a.predecessor)` returns null and `meta.machine` isn't this host (`packout.mjs` 326–358). The seat writes both `meta.session` (the report) and the `PREDECESSOR` footer (its handoff or start line). `findTranscript` returns null for **zero or several** hits. The downgrade branch never consults the on-disk state and needs no `check` row.
- **Evidence:**
  - *(fixture, `probes-c.txt` GHOST)* A C1-FAIL packout, with the report's `session` set to `ffffffff-0000-…`, `machine` to `SOME-OTHER-HOST` and C1 to PASS, and the footer naming the same ghost → **`VERIFY DOWNGRADED … NOT a pass`, exit 3.** The state for that handoff exists on this machine (`true`).
  - *(fixture, DUP)* A copy of the transcript under a second project folder plus an edited `machine` → **DOWNGRADED, exit 3**. With the honest report it is a FAIL ("made on this machine, but no transcript…").
  - *(real, §4)* AC-PG's FAILing report, copied **anywhere** with the ghost edits → **DOWNGRADED, exit 3**.
- **Why it matters:** spec §3.3 makes the downgrade a proceed path ("the successor says so in its Report #0"). This is QC2's N1 again, one field further along.
- **Fix sketch:**
  - **(a)** If `state.json` for `meta.handoff` exists on this machine, never downgrade. It lives under `~/.claude`, so its presence proves the same machine. Also require `a.predecessor ∈ state.sessions`.
  - **(b)** Treat `findTranscript` ambiguity (more than one hit) as a FAIL, not as absence.
