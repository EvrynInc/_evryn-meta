🔴 The protection is inverted

Across 13 deliberate breakages over two review passes, a clean split emerged. The mail-handling layer is genuinely defended — every attempt to break it went red.

Everything inside the one big file went green. Five security doors, the runaway-cost kill switch, the silence watchdog, both halves of the operator gate — broken on purpose, nothing noticed.

Same mechanism every time: the decision-making pieces were pulled out to make them testable, and are tested well. The machinery that runs them is unguarded — and 1,925 passing assertions is exactly what stops anyone looking.

What this picture says

Read the fills. Nearly everything that is actually the product — matching, connections, payments, the web app, the trust graph — is an unbuilt outline. The one solidly filled column is gatekeeper email.

That isn't a criticism. v0.2 is a deliberate beachhead. But it's the thing the codebase can't tell you, because the codebase is 20,000 lines of the sidecar.

Turn on "Which file does this"

One file — src/triage/classify.ts, 3,188 lines — is responsible for five separate boxes across three bands. But it isn't five equal fifths: it's 51% tool definitions, 19% prompt assembly, 15% safety. One dominant mass sharing a house with two lodgers.

🔴 And the file called triage/classify.ts contains no triage and no classification. That work lives in email/process.ts, triage/verdict.ts, and a markdown file. The name has been pointing at the wrong thing.
