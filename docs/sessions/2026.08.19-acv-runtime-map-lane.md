### ✅ The fix for the layer-color collision (Justin's catch — it was a real flaw)

**The bug:** every active layer set the box's **stroke**. A box in two active layers had two rules competing for one property, and **CSS source order silently decided the winner** — so "what decides which predominates" had no answer a user could reason about.

**The fix: layers stopped using the outline.** Each box now carries a **stacked stripe on its left edge** — one segment per active layer it belongs to, dividing the edge evenly. Three layers on a box render as three segments. **Nothing overwrites anything, and the count is readable at a glance.** Generated in JS from each box's own rect, so the stripe can never drift from the box it describes.

**The outline is now free**, and selection was moved off stroke-weight onto an **offset halo**. ⇒ **Stroke weight is now an unspent channel.** Deliberately held rather than spent on something marginal; the natural future use is **edge thickness = how much traffic actually flows**, which is exactly the thing the dependency map admits it cannot know.

## 🔔 THE MAINTENANCE MODEL — designed, needs Justin's ruling before it is built

**His question:** who maintains this, what triggers it, and how does it *"bug me (and Soren once he's autonomous) just the right amount"* without bogging down every `#lock`?

### The insight the whole design rests on: the Map has TWO halves with completely different staleness rates

| Half | What it is | How fast it rots |
|---|---|---|
| **The shape** | which boxes exist, which band they sit in, how they relate | **slowly** — only when the product design changes |
| **The state** | what is built / deployed / switched off, file sizes, gap counts | **constantly** — every merge |

🔴 **Maintaining them with one mechanism is what would bog us down.** Almost everything that goes stale is *state*, and **state does not need a human at all.**

### ⇒ Four mechanisms, each aimed at what it can actually catch

1. **STATE → machine-refreshed. Zero human cost.** File sizes, flag settings, what is deployed, the import graph — all already derivable, and `npm run depmap` is already the instrument. **This removes the bulk of the rot from anyone's plate.**

2. **RUNTIME SHAPE → the trigger is a DIFF, not a DATE.** `npm run depmap` produces a **byte-identical** JSON against unchanged code, so **a non-empty diff means the shape actually moved.** The Map stores a fingerprint of what it was drawn against; a check compares it to the live tree. **If nothing moved: silent, costs nobody anything.** If something moved: **the Map's own header banners it and names the files** — self-announcing at the point of use, which is exactly when it matters.

3. **DESIGN SHAPE → routed, not remembered.** When ARCHITECTURE or a BUILD doc changes, the Map may need to change. That is precisely what `doc-update-routing-protocol.md` is for — it maps a change-type to every surface it touches. **Add the Map to it.** ⇒ Mechanical, not memory-based.

4. **BACKSTOP → ONE line in `#lock`:** run the check; if red, update or record why not. **~10 seconds when green, and green is the common case.**

### 🔑 The part that keeps this from doubling the burden

**The Code Atlas already carries an identical standing order** (*"a build that changes the runtime's shape is not done until the Atlas reflects it — same commit or merge"*). **Adding a second artifact with its own separate discipline would double the obligation and halve compliance with both.**

⇒ **Make it ONE beat, two artifacts:** *"a build that changes the runtime's shape updates the Atlas AND the Map."* One rule, one moment, the person who moved the code does both — because they are the only one who knows what moved.

### Ownership + escalation

- **Soren owns it of record** (he owns `ARCHITECTURE.md`, and the Map is now prescriptive).
- **Whoever moves the runtime's shape updates it** — same as the Atlas.
- **Escalation is by AGE, so it nags proportionally:** banner amber when the fingerprint diverges; **red, with a day count, once it has been stale for more than a week.** A quiet check that never nags is how a map rots; a check that nags every day is how a map gets ignored.

**⚠️ What I deliberately did NOT propose:** a hand-maintained *"Map last updated: …"* line in `current-state.md`. **That is the exact shape that has rotted here before** — a date somebody has to remember to bump. The fingerprint computes itself.

> **ON JUSTIN'S BALLOT:** approve this model (and the one-beat merge with the Atlas), or adjust. **It is not built** — the check script and the banner are real work, and I would rather build the agreed shape once.

## The design — settled

### Why not the thing everyone builds

An auto-generated import graph (45 files, 361 edges) is the standard answer and it is the wrong one. Five reasons, each of which dictated a design choice:

| Why the node graph fails | What we do instead |
|---|---|
| Answers "what imports what" — a refactoring question, asked twice a year | Draw the **flow**: what arrives, what decides, what leaves |
| Every edge weighs the same (our own dependency map admits *"edge existence is not edge weight"*) | **Line thickness = real traffic**, by human judgment |
| No top, no bottom — a hairball destroys sequence | **Position is fixed and never re-laid-out**, so the geography is memorable |
| Shows structure, not behavior | Overlays for money, safety, security, identity |
| 🔴 **Can only draw what exists** | The **gap layer** — the highest-value content, and structurally impossible to generate |

**Prior art:** the methodology is **C4** (draw a system at fixed zoom levels rather than one flat picture). We borrow the zoom-level idea and reject the auto-layout renderers, because auto-layout rearranges on every render and that is precisely what stops anyone building a mental map.

### Three zoom levels

- **L1 — The Product.** ~20 boxes in five bands, the whole of Evryn as designed at v0.3. **This is where the sidecar point lands.**
- **L2 — Inside one box.** The built pipeline in detail (mail arrives → dedup → sender resolution → screen → judge → verdict → draft → approval → send).
- **L3 — The code.** Which files implement a node, their size, their Atlas section.

### The encoding rule — one channel, one meaning

**This is the rule that keeps three layers legible at once**, and the reason it works is that no channel does double duty:

| Channel | Carries | Never carries |
|---|---|---|
| **Position** | the flow — fixed forever | anything else |
| **Color hue** | which layer/concern | build state |
| **Fill** | does it exist? (solid → live · muted → merged not deployed · hatched → built but OFF · translucent → designed · outline → sketched) | concern |
| **Border** | how well specified (solid → has an ADR · dashed → loosely sketched · dotted → gap, nothing written) | |
| **Line thickness** | how much actually flows | |
| **Badge** | process state (live · undeployed · off · this sprint · next · designed · ⚠ gap) | |

If color carried both concern *and* state, multi-layer becomes mush. It doesn't.

### The layers (toggles)

**Security · Safety & retries · Data · Identity · Gaps · Code overlay.**

**The gap layer draws two kinds of missing, and never lets them look alike:**
- **Documented gap** — a doc says X should exist; the code lacks it. Carries both citations.
- **Judgment gap** — no doc mentions it, but conventionally it belongs (a retry, a rate limit, an idempotency key, an alert). Drawn lighter and **labelled as judgment, not as a finding.**

🔴 **A confident-looking map that is quietly guessing is worse than no map.** That is the exact failure this whole artifact exists to end (`atlas/00-INDEX.md`: *"an agent with no map knows it has to go and look"*).

### The refactor falls out for free

The **code overlay** shows which file implements each conceptual box. When **one file lights up across six boxes**, that *is* the `classify.ts` god-module problem, drawn. **The refactor is done when every box has its own file.** The map becomes the scoreboard — which answers Justin's *"how do we map out the refactor?"*

### Static vs live — the honest split

- **Geometry and meaning: hand-authored.** No tool knows that one line in the poll loop is the most consequential decision in the codebase.
- **Facts inside it: machine-refreshed.** File names, sizes, flag states, import edges — all already generated by `npm run depmap`.
- 🔑 **The staleness alarm is what makes it survive.** The map stores a fingerprint of the code it was drawn against; a check script diffs it against the live tree and the page banners *"⚠️ N files moved since this was drawn."* **This converts the normal death of diagrams — quiet rot — into a visible signal.** Non-negotiable: without it this becomes the stale map the Atlas warns is worse than nothing.
- **Later, not v1:** the dashboard already reads Railway `/health` and the product DB, so the map can eventually light up with live state (breaker tripped? clustering on? which version is live?).
