# Changelog — _evryn-meta (cross-repo docs · dashboard · protocols)

> **Truncation check:** the last line of this file should read `FULL FILE LOADED`. If you don't see it, reload until you confirm the complete file.

**How to use this file:** reasonably concise entries per substantive change to **this repo**. Most recent at top; detail lives in git log.

**What rises to a changelog entry — and who writes it.** An entry records a **deploy or a substantive change** (code, identity, schema, a protocol, a doc, the dashboard) — the unit is a *ship/change*, not a session. **Session-management narration does NOT belong here:** a conductor recounting coordination with its lanes ("answered AC2's notes," re-spin logistics, routine pushes), or in-flight status that hasn't shipped, belongs in handoffs and git — not the changelog. **The AC responsible for a ship owns its entry** and — being contextualized on the work — routes it to each repo the change actually touched.

**Scope — `_evryn-meta`, and read by EVERY AC on load.** This changelog records changes to `_evryn-meta` itself: the Hub + spokes, protocols, ADRs, load cascades, `CLAUDE.md`, and the monitoring dashboard (`_evryn-meta/dashboard`). Every AC skims it on load — it carries changes to their own operating manual, the protocols, and the cascades. **Routing rule:** an entry belongs here **iff the change touched a file in `_evryn-meta`.** A cross-repo change that does **not** touch `_evryn-meta` gets **no** entry here — logging "two other repos changed" is pure noise and doubles what ACs already load per-repo. If a change touched `_evryn-meta` **and** another repo, log the `_evryn-meta` slice here and the other repo's slice there.

**Monthly archive:** at month-end, move the prior month's entries to `docs/historical/changelog-historical/changelog-YYYY-MM.md` (trailing by one month).

**Skim on full-cascade load:** this file's top ~100 lines + section headers (the changelog-skim step in your load cascade points here).

## 2026-08-06→10 (AC0-31 — TWO-TRIP SUBAGENT LOADING replaces the load-compliance problem; the Atlas-update standing order; four inherited claims found false)

- **🔴 TWO-TRIP LOADING — the biggest change to how we spin subagents since the tagged brief itself (Justin's design).** Every spin is now **two trips**: trip 1 sends `<identity>` + `<mandatory_load>` + `<receipts>` and **says nothing whatsoever about the work**; the spinner verifies the receipts against the list; only then is the agent **resumed** with `<task>`. **Why it works, in one line: every subagent that ever skipped a briefed file scored that file against the task while planning its first calls — so remove the task from the load trip and the failure has nothing to operate on.** One described it exactly: *"I triage the load list against the task as I read it — I never registered a moment of choosing to drop it."* This is a **structural invariant, not an instruction**; relevance is simply **not computable** from what the agent holds. **It is only possible because `resume` exists** — when subagents were one-shot, load and task *had* to arrive together, which is why all the pleading existed in the first place. — [Justin's design · AC0-31 wrote it]
- **What that let us DELETE, and what it cost.** Gone: the all-caps, the threats, the *"we already spun you once and you failed"* callout, the `STOP SKIMPING` rant, and the entire `<pre_task>` block — **all of it existed to talk an agent out of a triage it can no longer perform.** Kept: precise line-spanned file lists, canary checks, the cascade-reconcile clause, `#cascade-override`. **Receipts were promoted from an end-of-run backstop to the gate between trips** — they used to be read *after* work was already built on the load they describe. 🔴 **The cost, written into the protocol rather than left to be discovered: the subagent can no longer drop a file, but it can no longer notice one YOU left out either — the spinner's list is now the whole load with nothing behind it.** Mitigated by a new **trip-2-only permission to load MORE**, with an obligation to report anything loaded beyond the list, since that report is the spinner's only signal their list had a gap. — [AC0-31]
- **The load trip now explains WHY it withholds the task**, rather than just withholding it (Justin's refinement). A rule without a mechanism decays into a suggestion, so it names the failure directly and closes the inference route: *"You cannot make that judgment about work you have not been told about — which is precisely why you have not been told."* — [Justin · AC0-31]
